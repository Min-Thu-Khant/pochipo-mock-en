適用ルール / 構成の参照元

読みやすく、迷わず操作できるUI

Apple HIGを参照し、スマホ向けWebモックの共通ルールに反映。白・グレーを基調に、案件と報酬を引き立てます。

01 操作領域

一般操作は44pxを基準にします。ユーザー指定のコンパクト仕様はCTA30px、ヘッダー36px、丸ドット6px・間隔6pxを優先します。

根拠：Apple HIG

02 文字と色

カテゴリは11px相当・下部タブは12px相当、説明文は16px相当を基本に、remで拡大に追従。補助文字を濃くし、選択状態は色に加えて下線・太さ・マーカーで表します。

根拠：Apple HIG

03 ダイアログ

本文は通常の太さで読みやすく。獲得・権限の操作は40pxにし、主操作と副操作の間隔を統一。報酬の受け取り方は下部の選択シートとして表示します。

根拠：Apple HIG

04 表示の使い分け

アラートは問題や取り消せない操作の確認に使用。日常的な完了は画面内に表示し、報酬獲得の演出とは区別します。処理中は進行状況を示し、無意味な確認を求めません。

根拠：Apple HIG

05 動きと画面幅

Reduce Motionでは装飾アニメーションを短縮。狭い画面でもボタン文言を折り返し、セーフエリアを考慮します。

根拠：Apple HIG

確認範囲

ホーム・案件・アンケート・マイページの共通部品、報酬選択・エラーダイアログ、部品集を修正。iOSネイティブのDynamic TypeやVoiceOver実機検証は別途必要です。

ダイアログのルール・デザイン

判断が必要なとき・処理を続けられないときに使用。通常の保存完了や少額の獲得は通知で伝えます。

01 表示と閉じ方

同時に1枚。通常はEscまたは閉じる操作で終了し、元のボタンへフォーカスを戻す。背景クリックでは閉じない。

02 情報の順序

意味のあるアイコン → 結論の見出し → 理由・影響 → 操作。必要な条件はボタンより前に表示。

03 操作の配置

主操作を上、副操作を下に配置。曖昧な「はい・いいえ」を避ける。破棄確認では安全な操作を初期フォーカスにする。

04 大きさ・配色

幅342pxまで・画面左右16px以上。角丸16px、内側16px。白い面とコーラルの主操作。ボタン48px、間隔8px。

05 アクセシビリティ

native dialog、見出し・本文をaria属性で関連付け。Tab移動は内部に限定。アイコンと色だけで意味を伝えない。

06 処理中・エラー

処理中は二重送信を防ぐ。閉じることと処理取消を混同しない。中断できない処理は一定時間後に状況確認・再試行へ移る。エラーで成功や付与済みを表示しない。

状態と使用例

見本を開くボタンで表示・キーボード操作を確認できます。実際の送信・設定変更・ポイント付与は行いません。

縦・横の余白パターン

画面端16px（360px以下12px）、独立したセクション間24px、枠で区切るコンパクトなまとまり間16px、カード内・見出し下12px、行内8px・行上下6px、近接情報4px、スマホのダイアログ内16px。カテゴリとカルーセルは個別ルールを維持。外側の要素が間隔を持ち、子要素との余白の重複を避ける。

グラデーション

使用箇所はおすすめのサイドタブと報酬獲得ダイアログの主操作。通常CTA・ポイント記号・進捗・タブ・アイコンは単色 #D96F4B（非選択はグレー、白抜きは白）。方向は垂直軸（上→下）のみ。停止位置は0%・100%の2点。Topは#D96F4B、Bottomは#FF3B62。最新の指定色を優先し、この2色を変更しない。CSSは角度の基準が異なるためto bottom（180deg）で上→下を指定する。

線幅と曲率

輪郭全体に丸みを持たせる。カード・用紙・カレンダーの外形は24pxグリッド上で角半径5px、靴・ホーム・巾着は連続曲線で構成。単独の折れ線は曲率式を使用。中心線を基準に設計。Regularは外形・単独線2px／内部線1.5px。Boldは単独線3px／円・矩形2.5px／内部線2px。アプリはRegularを使用。角の中心線半径 r = (3 / √2) × x × sin(θ / 2)。90°・線幅2pxではr=3px。直線同士の接続角に適用し、円や人物などの連続曲線は形状として設計する。

デザイン方針

案件・バナー・報酬を引き立てるため、画面は白・グレー中心。アイコンは緑 #D96F4B と白のみ。グラデーションやピンクレッドの濃淡は使用しない。塗り面を抑え、曲線を主体とした丸い輪郭で形を表現する。24pxグリッド・線幅2px・丸い線端と角を共通化。

アイコンと状態

- 非選択タブのみグレースケール・不透明度60%。選択タブとコンテンツ内はピンクレッド・白で表示。

- searchは虫眼鏡、userは頭と肩、お得はコイン入り巾着袋、右上ミニゲーはサイコロ。

- ゲームの十字キー・ボタン、カードの帯は輪郭の中に間隔を取り、線が潰れないよう描く。

- Pマークはピンクレッド地に白。ピンクレッドのCTA上のアイコンは白。

余白の詳細仕様

文字の太さ：全画面共通

進捗（0/0）・本日分終了・件数・残り時間・補足・状態ラベルは400。CTAと絞り込みは600、見出しは700。進捗数字は等幅数字で揃えます。

関連する情報は近く、異なるまとまりは離し、外側から内側へ余白を小さくします。参考：SmartHRの余白設計

以下は本アプリ向けの採用値です。ファーストビューの情報量を保つため、カード内・見出し下は12pxを維持。独立したセクションだけ24pxで区切ります。画面が狭くても縦の間隔は変えず、左右のみ12pxに縮めます。

単位はCSS px。画面端・まとまり・部品・補足の順で余白を使い分けます。

全タブ共通：ドット・絞り込み・CTA

ホーム・お得・簡単・マイページの共通部品へ適用。進捗とカルーセルの丸は直径6px・間隔6px。絞り込みと一覧内CTAは高さ30px・左右10px・部品間8px。画面の主操作は高さ40px以上・上下8px／左右12px。カテゴリのアイコンタブは専用寸法を維持します。

個別部品の例外

  • カテゴリ列：左右8px、項目間gap 0px、アイコンとラベル4px。項目幅は列の内幅÷6.4（約6.4個を表示）。
  • カルーセル：丸6px・丸同士の見た目の間隔6px。インジケーター行は20px。
  • ミッション・動画CTA：高さ30px、左右padding 8px。高さと余白は別に管理。
  • ヘッダー：ミニゲーは42×36px・枠なし。残高は高さ36px・左右padding 4px／6px。

余白を重複させない

セクション間24pxは後続要素の上側だけで確保し、前の要素の下余白とは合算しません。カードの12pxは内側、画面端の16pxは外側です。カード内の本文は画面端から28pxになり、カード外の見出しとは階層が異なります。

画面幅 > 360px: --page-gutter: 16px;
画面幅 ≤ 360px: --page-gutter: 12px;
カード: padding: var(--card-inset);
ミッション行: gap: var(--row-gap);
             padding-block: var(--row-inset-y);

文字の統一ルール

チャレンジボーナスの見出し行（トロフィー・見出し・説明リンク）は左揃え。案件カード内の情報は中央揃え。「チャレンジボーナスとは」は見出しの隣に10px／400、間隔4pxで配置（360px以下は9px）。

下部ナビは選択バーなし。上部カテゴリと同じく選択700・非選択400とし、アイコンと文字の色でも選択を示します。検索欄は白背景・検索アイコンと「検索する」のプレースホルダーを表示。検索ボタンは置かず、Enterで検索します。検索欄→告知→カテゴリは間隔8px、カテゴリ下12px。

アフィリエイト一覧：グレー背景に白いカードを3列。画像→報酬→案件名の順。カード内12px、カード間12px、要素間8px、角丸8px。案件名11px・最大2行、報酬14px、補助9px。

お得タブの案件名は、3つのサブタブ共通で12px／600／行高1.5。

文字のみのサブタブ：おすすめ・ガポガポ・すぐできる／マイ案件は13px、高さ44px、上下8px・左右4px。選択700・非選択400、色と下線も併用。

全タブの一覧：項目名14px／600、補足12px／400、報酬16px／700。P記号はpoint-symbol.jsを共用し、通常16px、残高28px、獲得演出36px。残高・獲得演出は一覧と異なる表示階層です。

視認性を優先し、同じ役割・同じ状態を画面間で統一します。ナビと絞り込みは選択700／非選択400。色・下線・背景も併用して選択状態を示します。
