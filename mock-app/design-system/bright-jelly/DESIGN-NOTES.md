# 表現の採用理由と検証方法

## 参考にしたもの

1. 指定フォルダ `pochipo/output/imagegen/bright-jelly-v1` のパレット・カレンダー・コイン・シューズ・スマホを目視。
2. [提供された調査メモ](references/ui-motivation-references-2026-09-18.md) を読み、研究・企業の自己報告・機能紹介・視覚的な観察を分けて利用。
3. 添付のDuolingo画面6点を目視。経路画面の押せる厚み、ショップの受取可能／獲得済み、達成画面の大きな報酬と次の操作を観察。
4. 現在のぽちぽの `app.js` と共通部品を確認。ヘッダー、8カテゴリ、バナー、ミッション、固定4メニューの骨組みを継承。

今回、元資料に載った論文・公式ページの再調査や効果測定は行っていません。研究結果の説明は提供メモによる整理を参照しています。添付静止画から実際のアニメーション時間や操作フローを測定したわけではありません。

## 参考画面から採用したこと

| 観察できた表現 | ぽちぽでの採用 | 配置 |
| --- | --- | --- |
| 白い広い面＋鮮やかな操作部品 | 文字・一覧は白、主操作に緑、進捗に青 | 基本トークンと各部品 |
| ボタン／アイコンの浅い下辺 | 4pxの下辺と短い押下反応 | BJ-A01 |
| 受取可能と獲得済みの区別 | コイン付きの受取、チェック付き受取済み | BJ-P02 |
| 報酬を大きく見せる達成画面 | 獲得量・理由・続けるをセットに | BJ-P06 |
| 日々の進捗や節目 | 実数の進捗、任意で使える週の記録 | BJ-P03〜05 |

既存の構成が条件なので、曲がりくねったステージマップ、ショップの商品構成、ランキング、他社キャラクターは取り入れていません。ユーザーがこれまで指定した「単色のミッション背景」「犬なしダイアログ」「固定フッター」「重複する進捗バッジなし」を守っています。

## 根拠と設計仮説の対応

| 狙い | 元資料での根拠の種類 | 今回の設計仮説 | 部品 |
| --- | --- | --- | --- |
| 進歩を実感できる | 目標勾配研究、Appleの進捗表示事例 | 現在値と残りを見せれば次の行動を判断しやすい | BJ-P01 / P03 / P04 |
| 行動の結果がわかる | Finchの報酬の使い道、Duolingoの達成反応事例 | 増分・理由・残高を同時に示せば受取結果を理解しやすい | BJ-P01 / P02 |
| 達成を喜べる | Duolingoのアニメーションに関する企業報告 | 節目に短いお祝いがあると達成感が増す可能性 | BJ-P06 |
| 押せることがわかる | 添付画面の視覚的観察 | 浅い厚みと押下反応がボタンの理解を助ける | BJ-A01 |
| 親しみを持てる | 指定の生成素材、Candy Crushの質感の観察 | 丸い形と控えめなツヤで報酬らしさを出せる可能性 | BJ-F02 |

研究はこのパレット・質感・動きの優位性を直接検証していません。神経科学の基礎研究から「このUIでドーパミンが出る」とは結論づけません。配色は指定素材のコンセプト案で、研究から最適な色値や面積比を導いたものではありません。

## 配色の扱い

緑 `#58CC02`、青 `#1CB0F6`、赤 `#FF4B4B`、黄 `#FFC800`、紫 `#A855F7`、橙 `#FF9600` は素材のプロンプトにある値を採用しました。PNGの画素から抽出した値ではありません。色の正本は `tokens.css` とし、日本語の見本はHTMLで表示しています。

明るい緑・青・黄の上は `#243B35` の濃色文字に変更。画像パレットの白文字をそのまま小さいUIに使わず、読みやすさを優先しました。小さい緑文字には `#285A0B`、青文字には `#075174` を使用します。これらは今回の補助色です。

多色の主役は提供4アイコンに限定。その他の操作アイコンは既存SVGを使うため、全アイコンのジェリー化を完了した版ではありません。

## 動きのルール

- ボタンは押下時にだけ沈む。常時バウンドしない。
- 受取操作を受け付けたらすぐ状態と数値を変え、コイン演出はその確認を補う。
- 5枚のコインはそれぞれ640ms、開始を55msずつずらす。最長860msで終わる。
- 初期サンプルは1回のみ受取可能。実際の付与はなく、メモリ内で二重加算を防ぐ。
- 普段の受取は非遮蔽の短い通知。節目のダイアログは部品集から試す候補。
- OSの動きを減らす設定と検討用スイッチを尊重。音や振動は未実装。

## チームで確かめること

1. 「何が完了したか」「何pt受け取ったか」「次に何ができるか」を説明できるか。
2. 進捗から残り量を正しく読み取れるか。受取可能と受取済みを区別できるか。
3. 立体ボタンの押しやすさ、連打、誤タップ、受取状態の理解。
4. 静止した完了表示と短い獲得演出を比較し、達成感と煩わしさを両方確認。
5. 配色・質感の比較は演出の比較と分ける。継続率や対象行動の完了を検証し、滞在時間だけを成功としない。

目標の選択や週の記録を実アプリへ追加するか、節目を何日にするか、演出をどの頻度で出すかはチームで決める仕様です。部品の見本から自動的に確定させません。
