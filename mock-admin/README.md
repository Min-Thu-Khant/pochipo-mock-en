# mock-admin：管理画面モック

ユーザー向けアプリのモック（`../mock-app`）を実現するための運用画面。アプリと同じ localStorage の状態を読み書きするため、同じブラウザーで両方を開くと、管理画面の変更がアプリ側に即時反映される。

## 起動

リポジトリのルートで `npm start` → http://localhost:4173/mock-admin/ （アプリは http://localhost:4173/mock-app/ ）。`npm test` でアプリ・管理画面のロジック検証。

## 画面と既存仕様の対応

| 画面 | 内容 | 既存仕様（poikatsu-spec） |
|---|---|---|
| ダッシュボード | 配信中の枠、審査待ち、デモ利用者のポイント、ミッション進捗、日次交換総額 | — |
| 運用枠 **新規** | バナー（最上部）・キャンペーン（ブースト）・おすすめ・チャレンジボーナス・テキストバナー・告知を 1 つの枠として入稿。表示位置（ホーム最上部バナー／ホーム特集枠／おすすめ枠／起動時ポップアップ／ためトク テキストバナー／チャレンジ枠）、期間、対象者、優先度、報酬モード、エントリー制、ミッション化、お知らせ文、リンク先（ディープリンク）。妥当性検査・複製・停止・削除・プレビュー | 該当なし。現行は Braze バナー／アプリ内メッセージ（`domains/braze-*.md`）と案件画面設定に分かれる。最上部バナーは Braze `home_first`（320×100、1 枚、トルツメ）に相当 |
| 特集ページ **新規** | 最上部バナー等のディープリンク先 `feature/<id>`。案件を集約した一覧、または 1 案件の特集。ID・タイトル・リード・注記・案件の選択。枠から参照中は削除不可 | 該当なし。現行のバナー遷移先はアプリスキームで案件詳細・グループ案件一覧・アプリ内ブラウザ |
| 案件画面設定 **spec** | 画面コードごとの設定（適用開始日時・グループ階層）。適用中／予約中／過去の判定、予約は画面ごと最大 3 件。アプリは `tametoku_quick` をためトクのクイックアクセスとカテゴリチップに、`home_quick` をホームのカテゴリタイルメニューに使う | `admin/affiliate-screen.md` |

| デイリーミッション報酬 **spec** | タスクごとの報酬（1〜99,999 pt、合計の 1 日上限）。即時反映。タスクの有効／無効とアンケートタスクは**新規** | `admin/daily-mission-task-reward.md` |
| アンケート還元率 **spec** | 種別（モニタ情報取得／スクリーニング／本調査）ごとの還元率と換算例 | `admin/survey-redemption-rate.md` |
| 審査・交換上限 **spec** | 付与予定の一覧、自動判定の実行、有人審査の承認／却下、日次交換総額上限 | `admin/point-grant-review.md`、`jobs/point-auto-review.md`、`admin/dotmoney-exchange-cap.md` |
| 成果・解禁 | NACS からの成果通知（承認・否認）の**再現**（運用機能ではない）、インストール案件の解禁／再ロック **spec** | `jobs/affiliate-conversion.md`、`admin/install-affiliate-unlock.md` |
| 実績 **新規** | 枠ごとの imp／tap／cv、成果ステータス、アンケートの開始・完了、CSV 保存 | 該当なし（行動ログと Braze 計測に分かれる） |
| 変更ログ | 変更系操作の記録 | 各 admin 仕様の「監査・記録」 |

## 試せる操作

1. 運用枠 →「秋のおでかけ応援」を編集して報酬や期間を変える → アプリのホーム特集枠・案件詳細に反映。
2. 運用枠 → 新規作成で種別「テキストバナー」・表示位置「ためトク テキストバナー」・リンク先 `challenges` → アプリのためトク検索窓の下に追加。
3. 付与設定 → 動画リワード 1 回のポイントを成人 200pt で即時適用 → アプリの動画セクションの表示が変わる。未来日時で予約し、確認日を進めると適用される。
4. デイリーミッション報酬 → 報酬を 999 にすると合計上限で拒否される。
5. 審査 → アプリで動画視聴・歩数獲得 → 管理画面に付与予定が並ぶ →「ポイント自動判定を実行」で交換可能へ。案件はアプリで「チャレンジ」→ 成果・解禁で「承認」→ 審査で「有人審査を一括承認」。
6. 案件画面設定 → `tametoku_quick` に新しい設定（グループを絞る）を作成 → アプリのクイックアクセスが変わる。

## 制約

- 権限（管理者ロール）・社内認証・確認ダイアログの文言は再現していない。
- 成果の発生・承認・否認は NACS が正であり、管理画面の機能ではない。「成果・解禁」画面は外部イベントの再現。
- 案件一覧コード（NACS）は持たず、案件のカテゴリで代替している。
