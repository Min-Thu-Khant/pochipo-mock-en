# mock-admin：管理画面モック

ユーザー向けアプリのモック（`../mock-app`）を実現するための運用画面。アプリと同じ localStorage の状態を読み書きするため、同じブラウザーで両方を開くと、管理画面の変更がアプリ側に即時反映される。

## アプリ構成（2026-09-16）

- **下部ナビ**：ホーム／お得／簡単／マイページ
- **お得**のサブタブ：おすすめ／ガポガポ／すぐできる／マイ案件（おすすめのみ検索あり）
- **簡単**：アンケート主軸
- **マイページ**：マイ案件・友達招待・ドットマネー交換
- **チンチロ**：右上・動画後抽選・小当たり 100pt（本管理画面の「チンチロ」で操作）

## 起動

リポジトリのルートで `npm start` → http://localhost:4173/mock-admin/ （アプリは http://localhost:4173/mock-app/ ）。`npm test` でアプリ・管理画面のロジック検証。

## 画面と既存仕様の対応

| 画面 | 内容 | 既存仕様（poikatsu-spec） |

| ダッシュボード | アプリ構成（4 タブ／お得サブタブ）、目減りゼロ ON/OFF、チンチロ状況、配信中の枠、審査待ち、ポイント、ミッション、日次交換総額 | — |
| 運用枠 **新規** | バナー（最上部）・カテゴリ広告（ホーム各タブ／お得：ガポガポ・すぐできる）・キャンペーン・おすすめ・チャレンジ・テキストバナー（お得）等を入稿。リンク先に `offers` / `high`（ガポガポ）/ `quick` / `surveys`（簡単）等。妥当性検査・複製・停止・削除・プレビュー | 該当なし。現行は Braze と案件画面設定に分かれる |

| 審査・交換上限 **spec** | 付与予定の一覧、自動判定の実行、有人審査の承認／却下、日次交換総額上限 | `admin/point-grant-review.md`、`jobs/point-auto-review.md`、`admin/dotmoney-exchange-cap.md` |

## 試せる操作

1. 運用枠 →「秋のおでかけ応援」を編集して報酬や期間を変える → アプリのホーム特集枠・案件詳細に反映。
2. 運用枠 → 新規作成で種別「テキストバナー」・表示位置「お得 テキストバナー」・リンク先 `challenges` → アプリのお得・おすすめの検索窓の下に追加。
2b. 運用枠 → フィルタ「カテゴリ広告」→ 「星ねこクエスト」を編集して見出しを変える、または停止 → アプリのホーム「ゲーム」タブ上部の広告が変わる／消える。
2c. 案件画面設定 → `home_tabs` に新しい設定（タブを 5 つに絞る）→ アプリのホーム上部タブが変わる。
3. 付与設定 → 動画リワード 1 回のポイントを成人 200pt で即時適用 → アプリの動画セクションの表示が変わる。未来日時で予約し、確認日を進めると適用される。
4. デイリーミッション報酬 → 報酬を 999 にすると合計上限で拒否される。
5. 審査 → アプリで動画視聴・歩数獲得 → 管理画面に付与予定が並ぶ →「ポイント自動判定を実行」で交換可能へ。案件はアプリで「チャレンジ」→ 成果・解禁で「承認」→ 審査で「有人審査を一括承認」。
6. 案件画面設定 → `tametoku_quick` に新しい設定（グループを絞る）を作成 → アプリのクイックアクセスが変わる。

## 制約

- 権限（管理者ロール）・社内認証・確認ダイアログの文言は再現していない。
- 成果の発生・承認・否認は NACS が正であり、管理画面の機能ではない。「成果・解禁」画面は外部イベントの再現で、本格的な操作（成果の発生・通知の停止・再送、案件の登録・報酬・掲出順）は `mock-nacs/` で行う。
- 案件グループは NACS の案件一覧コード（`listCode`）を持ち、その掲出順で案件を表示する。コードを持たないグループはナビ用（全案件）。案件の実データはタメルコ側では持たない。
