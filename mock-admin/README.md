# mock-admin：管理画面モック

ユーザー向けアプリのモック（`../mock-app`）を実現するための運用画面。アプリと同じ localStorage の状態を読み書きするため、同じブラウザーで両方を開くと、管理画面の変更がアプリ側に即時反映される。

## アプリ構成（2026-09-16）

- **下部ナビ**：ホーム／お得／簡単／マイページ
- **お得**のサブタブ：おすすめ／ガポガポ／すぐできる／マイ案件（おすすめのみ検索あり）
- **簡単**：アンケート主軸
- **マイページ**：マイ案件・友達招待・ドットマネー交換
- **チンチロ**：右上・動画後抽選・3つ一致＝大当たり／2つ一致＝当たり／すべて異なる＝ハズレ（本管理画面の「チンチロ」で操作）

## 起動

リポジトリのルートで `npm start` → http://localhost:4173/mock-admin/ （アプリは http://localhost:4173/mock-app/ ）。`npm test` でアプリ・管理画面のロジック検証。

## 試せる操作

1. 運用枠 →「秋のおでかけ応援」を編集して報酬や期間を変える → アプリのホーム特集枠・案件詳細に反映。
2. 運用枠 → 新規作成で種別「テキストバナー」・表示位置「お得 テキストバナー」・リンク先 `challenges` → アプリのお得・おすすめの検索窓の下に追加。
2b. 運用枠 → フィルタ「カテゴリ広告」→ 「星ねこクエスト」を編集して見出しを変える、または停止 → アプリのホーム「ゲーム」タブ上部の広告が変わる／消える。
2c. 案件画面設定 → `home_tabs` に新しい設定（タブを 5 つに絞る）→ アプリのホーム上部タブが変わる。
3. 付与設定 → 動画リワード 1 回のポイントを成人 200pt で即時適用 → アプリの動画セクションの表示が変わる。未来日時で予約し、確認日を進めると適用される。
4. デイリーミッション報酬 → 報酬を 999 にすると合計上限で拒否される。
5. 審査 → アプリで動画視聴・歩数獲得 → 管理画面に付与予定が並ぶ →「ポイント自動判定を実行」で交換可能へ。案件はアプリで「チャレンジ」→ 成果・解禁で「承認」→ 審査で「有人審査を一括承認」。
6. 案件画面設定 → `tametoku_quick` に新しい設定（グループを絞る）を作成 → アプリのクイックアクセスが変わる。

## 制約

- 権限（管理者ロール）・社内認証・確認ダイアログの文言は再現していない。
- 成果の発生・承認・否認は NACS が正であり、管理画面の機能ではない。「成果・解禁」画面は外部イベントの再現で、本格的な操作（成果の発生・通知の停止・再送、案件の登録・報酬・掲出順）は `mock-nacs/` で行う。
- 案件グループは NACS の案件一覧コード（`listCode`）を持ち、その掲出順で案件を表示する。コードを持たないグループはナビ用（全案件）。案件の実データはタメルコ側では持たない。

## バナー画像と特集のジャンル管理

運用枠と特集の「バナーをアップロード」からPNG・JPEG・WebP（10MBまで）を選択し、プレビュー後に保存します。配信先の規定ピクセルサイズを確認して、寸法を維持したWebPに圧縮し、同じブラウザのlocalStorageへ保存します。容量不足時はエラーを表示して入力内容を保持します。別端末への共有は未実装です。

バナー内の表示タイトル・説明・ブランド・装飾文字の編集欄は廃止し、完成画像の文字を使います。管理名・リンク先・配信期間などは別に設定します。既存バナーは画像登録まで元の見た目を維持します。

特集の案件選択は、案件名・ID検索、大ジャンル、小ジャンル、選択済みのみの表示に対応しています。各案件のジャンルを自由入力できます（旅行 → SIM／旅行会社など）。特集保存時に管理用タグとして全特集に共有します。NACSの案件カテゴリは変更しません。絞り込みで非表示になった案件も選択状態を保持します。

## 運用ナビゲーション

- TOP画面上部のメニュー：買い物・ゲーム・アンケートなどのメニュー構成。
- チャレンジボーナス：上へ・下へでアプリの表示順を変更。詳細・条件の編集はNACSへ移動。
- バナー広告：TOP・カテゴリ・ポップアップおよびキャンペーンページ内の画像差し替えを集約。
- キャンペーンページ：1つの特集に1件以上の案件を掲載。ジャンルで検索・選択。
- オトク内テキスト広告：検索窓下の広告文言、リンク先、掲載期間。

キャンペーンページ内の画像アップロードは「バナー広告」の下部へ移動しました。旧URL #slots / #features は新しい画面に読み替えます。チンチロは報酬・判定、案件グループ設定は確認メニューに配置しています。

## 全員共通のデイリーミッション設定

「運用 → デイリーミッション設定」で共通のミッション定義を保存します。アプリ起動・歩数・動画視聴も文言・説明・報酬・有効／無効を編集できます。達成を判定する種別は維持します。案件詳細閲覧ミッションは対象案件・遷移先リンク・文言・説明・報酬を編集し、追加・削除・無効化によって件数を調整できます。ユーザー別の設定はありません。既存の広告視聴可否の制御は継続します。

追加後に対象案件の詳細ページを開くと達成し、従来どおり受け取り操作で付与予定になります。設定前の閲覧は遡及しません。日付が変わると未達成に戻ります。同日の同一案件は削除・再登録しても二重付与しません。対象差し替え前の閲覧は新しい対象の達成として扱いません。既存の受け取り済み状態は設定保存で消しません。報酬合計が日次上限を超える設定や有効な同一対象の重複は拒否します。

遷移先リンクは `offer/案件ID`、`#offer/案件ID`、アプリ詳細ページのURLを指定できます。保存時に案件詳細への内部リンクに統一し、その案件の閲覧を達成条件にします。対象案件の選択でリンクが自動入力されます。


## バナーのリンク

NACSの案件編集またはキャンペーンページ編集でURLをコピーし、バナー編集の「リンク先の案件・特集ページ（URL）」に貼り付けます。同じホストのアプリURLを保存時に内部リンクへ正規化します。

## バナーカルーセルと配信枠

バナー編集は「配信枠 → 表示位置」の2段階です。ホーム枠には最上部・ゲーム／買い物／クレカの上部と下部・歩数の下部、オトク枠には高還元とすぐできるの上部、起動時枠にはポップアップがあります。

ポップアップは1設定に1枚、それ以外は1設定に1〜5枚を登録し、各バナーに画像・管理名・ディープリンクを設定します。対象者と優先度の編集欄はありません。画像バナーの配信は全員共通で、公開状態と期間を使います。ポップアップは有効な候補から均等に1枚を選び、300×250pxで単独表示します。それ以外は同じ表示位置の有効バナーをランダムに並べ、最大5枚を同じ5秒間隔で表示します。6枚以上の候補も等しい確率で選ばれます。ドット・横スワイプに対応し、操作中・画面非表示・動きを減らす設定では自動送りを停止します。

既存の単独バナーは配信を維持し、同じ枠にまとめて表示します。編集保存時は1〜5枚に揃えます。画像がない既存バナーは従来のデザイン、新規スライドはリンク先のサンプル表示を使い、アップロード後は画像を表示します。


## 配信先ごとの規定画像サイズ

| 配信先 | 必須サイズ |
| --- | --- |
| デイリーミッション中部（ミッション一覧と動画の間） | 320×50px |
| 特集ページ、ホーム最上部、チャレンジボーナス上部、カテゴリ広告上部 | 320×100px |
| POPUPメイン、カテゴリ広告下部 | 300×250px |

配信先を選ぶと全スライド共通のサイズを表示します。画像の実寸が異なる場合はアップロード・保存を拒否します。同じ比率でも640×200を320×100として登録することはできません。自動リサイズ・切り抜きは行いません。配信先変更後も既存画像のサイズを再検証します。アプリでも規定外の画像は配信せず、規定比率を保って表示します。未登録の画像はデモ用表示を使用します。

1200×628pxはサイズ定義のみ追加し、配信先の確認待ちです。

バナー広告は枠一覧から配信先を選び、その枠内で登録・編集します。ポップアップは300×250pxの単独表示、それ以外は1枚なら単独・複数枚ならカルーセル、配信対象が0枚なら枠全体を非表示にします。プレビュー、矢印、枚数カウンターは表示しません。ディープリンクはNACSの案件編集とキャンペーンページ編集でコピーできます。

## キャンペーンページの編集（2026-09-16）

`#campaigns` で掲載する特集名・紹介文（改行対応）・掲載開始日／終了日・掲載件数（上限）を設定できます。案件は名前・IDで検索し、チェックして選択します。カテゴリのプルダウンとジャンルの編集欄はありません。既存のジャンル設定は変更しません。

- アプリには特集名・紹介文・案件を表示し、掲載期間・件数の表示は出しません。画像がある場合も特集名と紹介文を表示します。
- 掲載期間は確認日を基準に開始日・終了日を含みます。空欄の境界は制限なし。期間外の特集ページには公開していない旨を表示します。入口の広告枠の掲載期間は別設定です。
- 配信停止・案件期間外・OS非対応・利用者の表示条件で除外してから、指定件数まで表示します。対象案件が少ない場合はその件数だけを表示します。
- 特集内の案件は保存した候補順です。NACS一覧コードのピン留め・クリック数順とは独立しています。
- 旧データの `note` 内の定型掲載期間を引き継ぎ、件数未設定なら従来の選択件数を上限にします。明示的に日付を空欄で保存すると期間制限を解除できます。
- 保存先は同一オリジンのブラウザー内 localStorage。実APIとの連携はありません。

`mock-admin/tests/campaign-publication.test.mjs` で期間の境界・旧データ互換・掲載件数・入力検証・ガポガポ／すぐできるのクリック順を確認します。


## チンチロ3段階と単独ポップアップ（2026-09-16）

- 役は `miss`（ハズレ／3つとも違う目）、`hit`（当たり／2つだけ同じ目）、`big`（大当たり／3つ同じ目）で固定。通常・初期テーブルそれぞれでウェイト、当たり・大当たりの倍率／固定ptを編集できます。ハズレは0ptです。
- ウェイトで抽選した結果に合うサイコロの目を表示します。ウェイト合計0や不明な役は保存できません。
- 旧 `small` のウェイトは `hit` に統合します。既存の当たり・大当たりの報酬と、利用回数・履歴は維持します。
- ポップアップは300×250px・1設定1枚です。旧設定に複数スライドがある場合は先頭の1枚を使用し、編集保存時に1枚に揃えます。複数の配信設定が有効な場合は1回につき候補から均等に1枚を表示します。
- 自動送り・ドット・スワイプ切り替えはありません。閉じる・あとで見る・画像からのリンク遷移は利用できます。
