# 会議から3成果物を揃える運用

## 通常の更新

1. 対象機能IDと未決事項をPRDから選び、会議で操作するモックを準備する。
2. 会議中は操作担当が画面を共有し、決定・提案・保留を区別して記録する。並行実装は機能と変更ファイルを分ける。
3. 会議終了後に原本を確認し、[会議記録](meetings/README.md)を保存する。根拠がない部分は推測で確定しない。
4. 既存PRDとコードの変更を照合し、既存機能の変更か新機能か判断する。新機能のみ採番し、PRD本文・完成条件・履歴を更新する。
5. 未反映のモックを修正する。画面で再現できない処理は「対象外」の理由と本番側の完成条件をPRDに残す。
6. `npm test`・`npm run check`・`npm run docs:check`と必要な画面操作を確認し、変更レビューで統合する。
7. 統合した版のPRDから機能一覧を更新し、元コミットと同期結果を記録する。

## 変更の単位

- 作業ブランチは`feat/PCH-F-0001-short-name`など。レビュー可能な機能単位にする。
- PRDとモックを同じ変更に含める。段階的な対応なら未反映箇所・担当・期限をPRDに明示する。
- 共通モデルや部品の変更では、他のモックへの影響も確認する。
- 仕様の確認者、モックの実装担当、統合担当を決める。既存の未コミット変更を消さない。
- 外部連携や自動同期は未設定。自動化していない手順を自動実行済みとして記録しない。

## 引き渡すとき

[引き渡し手順](handoff/README.md)に沿って対象の版を固定し、3成果物を揃えます。発注後も同じ機能IDで差分・理由・影響を記録します。
