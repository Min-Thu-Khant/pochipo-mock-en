# 議事録からPRD・機能要件表を更新する運用

## 通常の更新

1. 許可されたDrive内の原本を読み、決定・提案・保留を区別する。議事録や会議単位の要約はGitに保存しない。
2. [個別PRD一覧](prd/features/README.md)から対象IDのファイルを開き、必要に応じて既存モックを参照して差分を確認する。既存F01〜F18は再採番せず、新規機能だけ採番する。
3. 個別PRDの本文・達成条件・未決事項・変更履歴を更新する。共通方針・一覧・閲覧用HTMLもPRDの一部として揃える。出典URLと必要な該当時刻を残し、根拠のない内容は推測で確定しない。
4. 同じ機能IDの機能要件表を更新し、更新履歴は別の「更新履歴」シートに追記する。Phase・仕様状態を合意なく確定させない。
5. PRDと機能要件表のID・内容・Phaseの整合性、内部リンク、変更対象を確認する。PRDのGitへの共有は依頼された範囲で行う。

## 更新範囲

- 議事録から更新する成果物はPRDと機能要件表のみ。モック・コード・その他の成果物は別途依頼された場合に更新する。
- モックとの未反映箇所はPRDに記録する。議事録の取り込みだけを理由に実装・デプロイしない。
- 変更履歴はPRDと機能要件表の更新履歴シートで管理し、会議要約や新たな同期記録ファイルを毎回追加しない。
- 既存の未コミット変更は維持する。過去の記録を最新仕様として書き換えない。
- 自動取り込み・自動同期は未実装。実施していない処理を実施済みと記録しない。

## モックの更新・引き渡し

モックの更新依頼を受けた場合はPRDと照合し、変更に応じて `npm test`・`npm run check`・`npm run docs:check` と画面操作を確認する。[引き渡し手順](handoff/README.md)に沿って対象の版を固定し、モック・PRD・機能一覧の3成果物を揃える。

## Drive

フォルダ整理はユーザーが担当します。[許可済みの範囲](drive-access.md)を超えてアクセスしません。このフローだけで外部ファイル作成や公開が許可されたとは扱いません。
