# F07・F08・F09・F11・F12：ホームのダイアログ反映

更新日：2026-09-24。ベース：main `6068b50`。

ユーザー指定のFigma「タメルコ ver1.0」のホーム上に隣接する14種類を、Webモックに反映した。既存の機能IDとポイント付与・確定ルールを維持する。本番SDK、端末権限、サーバー側の再送処理の実装完了を意味しない。

仕様状態：既存要件案を維持。モック状態：実装済み、ブラウザーの表示・フォーカス確認は未実施。

## 目的と達成条件

| 機能ID | 目的 | 達成条件と反映内容 |
| --- | --- | --- |
| F07 | 日付の変更と報酬の受取結果を案内する | 検証設定で日付を変更すると日付切り替え案内を表示し、「更新する」で選択日の内容を表示する。実時間の0時の検知は今回の対象外。 |
| F08 | 歩数連携の方法と獲得方法を選べる | iOSとAndroidの案内、Androidの設定からの再許可案内、広告あり／なしの選択を表示する。報酬は現在の運用設定を使用する。Webでは端末設定の代わりに連携後の状態を試す確認画面へ進む。 |
| F09 | 広告の失敗理由が分かり、再試行または終了できる | 8種類のエラーを区別する。エラーや視聴中断では付与しない。再試行は元の操作に戻り、通常の上限・受取条件を再確認する。広告不可の利用者に広告選択を出さない。 |
| F11 | ミニゲームの動画にも同じエラー案内を使用する | 動画視聴の失敗時に抽選・受取を進めず、再試行できる。未受取の当たりは保持する。ゲーム固有の結果画面は従来のまま。 |
| F12 | 報酬額と獲得後の合算ポイントが確認できる | 共通の報酬獲得画面に実際の獲得額・合算ポイントを表示する。広告配信対象の場合だけ下部に広告枠を表示する。準備中から交換可能への確定処理は変更しない。 |

## 確認方法

1. モックを開き「表示・動作の確認」（狭い画面では「デモ設定」）→「ダイアログ一覧（14種類）」を開く。すべての表示と操作を確認できる。確認用ボタンではポイント・権限・日付を変更しない。
2. URLのクエリ `?dialog=step-select`、`?dialog=ad-empty` などでも直接表示できる。この場合も確認専用である。
3. 実際の歩数受取・動画視聴で結果画面を確認する。検証設定の「次の動画視聴で再現するエラー」は1回だけ適用し、再試行は通常の処理に戻る。継続的な「読み込み・送信エラー」設定やオフライン状態は解消するまで継続する。
4. 新規データは未許諾で始まる。既存の保存データの連携状態は保持する。検証設定「歩数計測の連携」を「未許諾」にして歩数タブを開くと、選択中のOSの案内を自動表示する。閉じた場合は画面内の「歩数の利用を許可」から再表示できる。「許可しない」で拒否状態を保存し、「設定を確認」で再案内を開ける。
5. 許諾は既存仕様のヘルスケア／身体活動へのアクセスであり、GPSの位置情報ではない。実際の端末権限・位置情報の取得は行わない。

### F08の追加達成条件

未許諾・拒否済みで歩数タブに入った場合だけ案内を自動表示する。許諾済み・利用不可の端末には表示せず、別のダイアログにも割り込まない。キャンセル・拒否で歩数報酬を付けず、明示的な許可操作でのみ連携済みへ進む。Androidの拒否済みには設定からの再許可案内を表示する。

## 検証と制約

- 原本イラスト29点をローカル保存。報酬イラストは原本SVGの構成と座標を保持する。原本画面の背景スクリーンショットは使用せず、現在のモック画面を背景にする。
- 原本のAmeba Sansはリポジトリにないため、数字はシステムフォントで代替。広告枠はモックのプレースホルダー。Figmaの30pt／5ptは確認専用表示に使い、実際の受取は運用設定値を維持する。
- 自動検証：原本素材の存在、確認専用操作、広告非対象、8種類の失敗時の未付与、再試行、視聴中断、ダイアログ差し替え、日跨ぎ、オフライン復帰、歩数の受取数維持。
- ネイティブの `dialog` によるモーダル表示、Escape／背景／ボタンでの終了、開く際のフォーカスと終了後の復帰を実装。ブラウザー操作ツールの実行環境エラーにより、実画面の見た目・キーボード操作は未検証。
