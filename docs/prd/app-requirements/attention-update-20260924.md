更新日：2026-09-24。根拠：ユーザーのホーム・お得画面への赤ポチ追加依頼。

目的：新しいお得な情報や利用できる機会を知らせ、対象画面の閲覧につなげる。
対象：F02ホーム、F03案件一覧、F05マイ案件、F06チャレンジ、F08歩数、F10アンケート、F11ミニゲーム、F12ポイント、F15テキスト広告。レシートの独立機能IDは未採番のため、今回はF02からの既存レシート画面への導線を扱う。

## 表示条件と達成条件

| 場所 | 赤ポチが出る条件 | 消える条件 |
| --- | --- | --- |
| ホーム左上のポイント表示 | 前回観測後に合算ポイントが増加した | ポイント獲得履歴を開く |
| 歩くタブ | 連携済みで、未受取の到達マイルストーンがある | 受取可能分をすべて受け取る、連携解除、日付変更等で対象がなくなる |
| チャレンジボーナスタブ | 表示対象に未確認の案件がある | チャレンジの一覧を開く |
| ゲーム・買い物・クレカタブ | 各タブの掲載一覧に未確認の案件がある | 該当タブを開く |
| アンケートタブ | 配信対象に未確認のアンケートがある | アンケートのタブまたは一覧を開く |
| レシートタブ | 掲載中・期間内に未確認のキャンペーンがある | レシートのタブまたは一覧を開く |
| ミニゲー（ホームのタブ・上部入口） | 今日挑戦できるゲームがある | 残回数がなくなる、停止・会員条件等で挑戦不可になる |
| お得の検索欄下のテキストバナー | バナーが未確認、または内容・リンク・掲載期間が更新された | そのバナーを押す。他のバナーは未確認のまま残す |
| マイ案件への入口 | 案件の追加、ステータス・段階進捗・ボーナス付与等の更新がある | 対象ステータスの一覧を開く。まだ開いていないステータスの更新は残す |

マイ案件内のステータスタブにも赤ポチを表示し、更新先を見つけられるようにする。歩数・ミニゲームの赤ポチは、閲覧しただけでは消さない。

## 既読と新着の判定

- 初めて確認する掲載案件は新着扱い。案件IDと掲載開始日で既読を記録し、並び順変更だけで再点灯させない。新規掲載ID・新しい掲載開始日の案件は再点灯する。
- 非掲載・掲載期間外・未解禁・対象外案件は新着の対象にしない。各一覧と同じモデルの掲載候補を参照する。
- ポイントの初期残高と既存マイ案件は初回導入時の基準にする。基準以降の増加・更新を通知する。ポイント減少では新たに点灯しない。準備中から交換可能への移動は合算が変わらないため再通知しない。
- 一覧の正常表示で既読にする。読み込み中・取得エラー・別ダイアログ表示中・非表示のブラウザータブでは既読にしない。
- 既読状態はブラウザーの専用ストレージに保存。リロード後も維持し、管理画面による共有状態の保存で巻き戻さない。「デモデータを初期化」では既読も初期化する。本番の会員単位・端末間の既読同期は未実装。
- ミニゲーは現在のチンチロの参加条件・残回数と、画面の1日3回の上限に合わせる。翌日の残回数回復で再表示する。

## 確認方法

1. 初回は未確認のカテゴリとテキストバナーに赤ポチが出る。該当一覧／バナーを開いて戻ると消える。
2. ポイントは動画視聴または連携済みの歩数受取で増やし、ホームの赤ポチと履歴閲覧後の消灯を確認する。
3. 歩数は検証設定で連携済みにし、1,000歩進めて受取可能数を変える。ミニゲームは遊び終えるまで表示される。
4. マイ案件は検証設定の成果承認／否認で更新する。対応するステータスを開くまで赤ポチが残る。
5. 管理画面でカテゴリ案件・レシートの掲載を追加し、既読後の新着を確認する。
