## 更新の流れ

1. スプシの最新Tier列を確認し、Tier1の要件IDだけを対象にする。
2. 現在のモックとユーザー指定に合わせて、本文・操作フロー・達成条件を揃える。
3. ⑤は実際の管理画面に基づき、新規作成・変更・削除の可否と管理元を分ける。
4. API・実機等の未接続は実装済みと扱わず、モックとの差として記載する。
5. 共通ルールを変えた場合はFMT・この一覧・全体PRDにも反映する。スプシの優先順位はPRD更新を理由に書き換えない。
6. ユーザーが第1版と指定した範囲を一覧にも反映する。版とレビュー状態は分け、未レビュー表示は明示的な解除指示があるまで残す。
