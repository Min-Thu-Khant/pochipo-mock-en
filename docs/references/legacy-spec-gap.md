# poikatsu-spec とプロトタイプ v2 の差分整理

作成日：2026-09-15。GitHub `ca-media-poi/poikatsu-spec`（main、最終更新 2026-09-14）を**読み取りのみ**で参照し、本プロトタイプ（tameruko-v2）との差分を整理した。リポジトリへの書き込み（編集・Issue・PR）は行っていない。

## 0. 前提と読み方

- **仕様書の位置づけ**：poikatsu-spec は「現在のサービスの振る舞い（最新断面）」の一次ソース。今回参照したファイルはすべて `status: active`（`home-composition.md` / `tametoku-composition.md` は `superseded` で、後継の `screens/home.md` / `screens/tametoku.md` を参照した）。
- **プロトタイプの位置づけ**：2026-09-15 の改修方針（AF ブースト・アンケート強化・円相当表記・診断なし）に基づく新バージョン案。現行仕様と一致させることを目的にしていない箇所も多い。本書は「何が違うか」と「どちらに寄せるべきか（判断が必要か）」を分けて記す。
- **凡例**（差分の種類）
  - **用語**：同じものを別の名前で呼んでいる。合わせるだけでよい
  - **表示**：表示条件・構成・文言の違い
  - **ルール**：達成・受取・付与・上限などビジネスルールの違い。実装前に決定が必要
  - **spec なし**：プロトタイプ独自の新機能。spec に該当がなく、新規仕様（`status: draft`）の起票対象
  - **未反映**：spec にあるがプロトタイプに入れていないもの
- 仕様書中の `<!-- 要確認 -->`（未確定・プラットフォーム差異）は、本書では「spec 側で未確定」として扱い、プロトタイプの判断根拠にしない。

## 7. 反映の進め方（提案）

1. **用語・文言を合わせる（低コスト・先行）**：合算ポイント／準備中／交換可能、受取済み、挑戦中／判定中／承認／否認、獲得完了ダイアログ文言、取得失敗・空状態文言、「チャレンジ」の用語衝突の解消。
2. **ルールを合わせる（決定が必要）**：達成と受け取りの分離（歩数・動画のミッション報酬を別付与に）、歩数の 1 回 1 マイルストーン＋獲得方法選択、動画セクションの配信可否、付与予定 → 確定の 2 段階（カテゴリ別の確定主体）、マイ案件の CV 単位・4 ステータス、最低交換ポイント 100 pt。
3. **構成を合わせる（デザインと相談）**：ヘッダーのマイ案件ボタン、Braze 枠の位置とサイズ（1 枚表示）、ためトクナビ＋クイックアクセス＋「全てのカテゴリー」、案件グループの件数上限、マイページの交換状態テキスト・失効予定。折りたたみと歩数の最上部配置は今回の要望として画面仕様の改訂案に含める。
4. **新機能は draft 仕様として起票**：5 章の各項目。特に「期間限定UP」「チャレンジボーナス」は NACS との責務分担が前提になるため、`integrations/nacs.md` と `jobs/affiliate-conversion.md` を含めて設計する。

### 9.2 仮値として残した項目（spec は運用設定で値を書かない）

デモ設定パネルに一覧表示し、コード内で【仮値】と明示。

| 項目 | 仮値 | 出どころ |
|---|---|---|
| 歩数：間隔 × 上限数 | 1,000 歩 × 4 回 | 現行キャプチャ |
| 歩数：1 回のポイント | 動画あり 300pt（3 円相当）／なし 100pt（1 円相当） | 仮 |
| 動画：上限回数 × 1 回のポイント | 3 回 × 100pt | 現行キャプチャ（回数） |
| ミッション報酬 | 各 100pt | 仮 |
| アンケート還元率 | モニタ 100%／スクリーニング 70%／本調査 70% | 仮（spec の例と同じ 70%） |
| 表示単位 | 円相当（P コイン付き） | 新方針。spec は pt 主表示・グループ単位で円 |

### 9.3 反映しなかった項目（判断が必要、または対象外）

| 項目 | 理由 |
|---|---|
| 3 タブ構成、ミッションカードの折りたたみ、歩数カードの最上部配置・コンパクト化 | 今回の要望による意図的なデザイン変更。画面仕様の改訂案として扱う |
| ポイ活タイプ診断セクション | 新方針で削除。spec 側の `superseded` 化が必要 |
| Braze バナー枠（位置・サイズ・1 枚表示）、アプリ内メッセージの保留・優先順位 | 運用枠とポップアップの構造そのものが新提案のため据え置き。表示ラベルに spec の配置名を併記 |
| デイリーミッションのアンケート／期間限定案件タスク、チャレンジボーナス、テキストバナー、エントリー制、期間限定UP | spec にない新機能（5 章）。名称の衝突（「チャレンジ」）は要決定 |
| 有効期限（失効日）、失効予定の表示 | N ヶ月の運用値が未確認のため文言のみ |
| セクション単位の読み込み・エラー表示、共通例外、行動ログ、許諾訴求、ページング | モックの対象外 |
