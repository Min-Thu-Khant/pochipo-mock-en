## 別添：NACS連携ガイド

本別添は、接続先であるNACSの役割と連携条件を説明する資料である。アプリ側の連携仕様を参照しており、NACSのAPI定義そのものではない。新アプリへの適用条件はNACS担当との確認が必要である。

### A. NACSの概要

NACSは複数ASPのアフィリエイト案件をまとめ、配信先アプリに一覧・詳細を提供し、クリックや成果を扱う社内サービスである。アプリを配信先の「チャネル」として識別する。NACS上のアフィリエイト案件IDをアプリの詳細表示やリンクでも利用する。

NACSはアフィリエイト案件と成果を管理する。自社アプリとバックエンドは、会員情報、画面への掲載設定、成果受信と承認・否認、ポイント管理基盤への連携を担う構成である。提供されたシステム概要ではポイント管理はGMOメディアの基盤へAPI接続する。台帳・確定判定の責務は別途確認する。動画リワード広告やレシートキャンペーン等のその他ポイント獲得機能をNACSがすべて管理するとは限らない。

### B. 連携の流れ

1. アプリのバックエンドが、NACSへアフィリエイト案件の一覧・詳細を問い合わせる。
2. ユーザーが参加する際、計測用のクリックURLを取得して遷移する。
3. ASPからの成果をNACSが扱い、承認等の状態を管理する。
4. 自社バックエンドは必要な成果通知を受け、GMOメディア側のポイント管理基盤へ連携し、依頼と確定結果を照合する。
5. 分析のため、クリックと成果のデータをBigQueryに取り込む方針である。取得可能な範囲とIDの対応関係はNACS担当と確認する。

### C. 連携条件と確認事項

| 事項 | 参考仕様の記述 | 今回の確認 |
|---|---|---|
| 識別・認証 | チャネル識別子と署名鍵を利用 | 新アプリのチャネル発行、認証の現行方式、鍵管理 |
| 一覧・詳細 | 一覧コードやOS等で取得。アプリはNACSの順序を使用 | 利用可能なフィルタ、ページング、終了時の応答 |
| クリックURL | アプリ側の既存仕様では発行時刻の前後30秒の署名。取得後すぐに開き、変更しない | 新接続の有効期限・署名主体・計測ID・再試行 |
| 通知のリンク | 短寿命のクリックURLを長期保存しない必要がある | プッシュからはアプリ内の詳細へ遷移し、参加操作時にURL取得する案 |
| 成果 | 発生・承認・否認の状態。ポイント登録は承認を利用する既存経路 | 分析で必要な各状態・訂正・取消を取得できるか |
| SUR | 複数段階で報酬が発生するアフィリエイト案件。段階別に重複防止 | cv_idとstep_id、更新版、再通知の契約 |
| 報酬 | 既存のアプリ向け値は還元計算済み | 広告収益・ユーザー還元の区別、金額・通貨・換算の契約 |
| 分析用の結合 | 今回必要な完全な結合契約は未検証 | 自社クリックIDとNACSクリックID・成果IDの対応可否 |
| 個人別表示 | 既存参考仕様だけでは対応可否を確定できない | セグメント入力、一覧切替、動的順位、NACSの開発範囲 |

### D. 必要な資料と検証環境

- 現行のNACS API定義とバージョン、認証・署名仕様、検証用チャネル・環境、サンプルリクエスト／応答。
- アフィリエイト案件の状態・条件・報酬項目・一覧コード・ページング・制限・エラーの定義。
- 成果通知の認証、イベントID、段階ID、状態遷移、再通知、重複・順不同・訂正時の扱い。
- 分析データの取得経路、取得可能なクリックID・成果ID、保持期間、鮮度、負荷・レート制限。
- 新アプリ接続の申請手順、担当窓口、障害時連絡、開発チームとNACS担当の役割分担。

### E. 参考仕様の範囲

読み取り専用の参考コピーを `references/` に同梱している。参照元は `ca-media-poi/poikatsu-spec` のコミット `f11f656f80a7032564376300645e34d5dada40b9`。NACS現行APIと一致するかは未検証である。原本は変更していない。参考コピー内の相対リンク先は一部同梱していないため、詳細はGitHubの固定版リンクを参照する。

- `references/nacs-integration-reference.md`：NACSへの依存内容・制約・障害時の扱い。[固定版原本](https://github.com/ca-media-poi/poikatsu-spec/blob/f11f656f80a7032564376300645e34d5dada40b9/docs/integrations/nacs.md)
- `references/affiliate-api-reference.md`：**旧アプリのバックエンドAPI**の意味論。NACSの直接APIではない。[固定版原本](https://github.com/ca-media-poi/poikatsu-spec/blob/f11f656f80a7032564376300645e34d5dada40b9/docs/apis/affiliate.md)
- `references/conversion-reference.md`：承認成果の受け取り・重複防止の参考。[固定版原本](https://github.com/ca-media-poi/poikatsu-spec/blob/f11f656f80a7032564376300645e34d5dada40b9/docs/jobs/affiliate-conversion.md)

参考仕様に含まれる旧アプリ固有の認証・参加条件・表示件数については、新アプリへの適用範囲を個別に確認する。同梱ファイルはGitHubのアクセス権限がなくても参照できる。現行API定義と検証環境は、NACS担当から別途提供する想定である。

NACSは内製であり、分析用の追加APIや履歴出力を相談できる。ただしASPから提供されない広告主サイト内の行動等は、NACS側の変更だけで取得できるとは限らない。内製アンケート、社内別部署のレシートシステムのデータ連携は、それぞれの担当と個別に確認する。
