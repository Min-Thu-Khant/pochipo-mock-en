# 機能一覧

機能ID・機能名・優先度・仕様状態などの編集元は[機能別PRD](../prd/README.md)です。Google Sheetsは一覧表示・レビュー用に使います。Drive上の整理はユーザーが行い、自動作成・編集はしていません。

## 既存の機能一覧

[アプリの機能要件定義ドラフト](../prd/app-requirements/requirements-draft.md)に18機能（F01〜F18）の一覧があります。既存IDと優先度案を維持し、個別PRDへ分割する場合は対応を記録します。ドラフトの優先度を承認済みとして扱いません。

## 一覧の列

| 列 | PRDでの対応 |
| --- | --- |
| 機能ID | 基本情報：機能ID（行の識別キー） |
| 機能名・概要 | タイトル・①目的 |
| 対象領域 | 基本情報：アプリ／管理画面／外部連携等 |
| 優先度・優先理由 | 基本情報：初回必須／できれば初回／後続／未決と理由 |
| 対象リリース | 基本情報：対象リリース（未決可） |
| 仕様状態・モック状態 | 基本情報：それぞれ別の列 |
| 担当者・更新日 | 基本情報 |
| PRDリンク | Git上の対象PRD |
| モックリンク | ②画面イメージの対象画面・状態 |
| 依存機能ID | 基本情報：依存機能ID |
| 未決事項 | ⑦の要約 |
| 根拠会議ID | 基本情報と変更履歴 |

優先度・リリースと、全体構想のTier／Phaseは別概念です。機械的に相互変換しません。

## 採番

- 新規の個別PRDは`PCH-F-0001`形式。未使用番号を統合担当が割り当て、PRD作成と同じ変更に含める。既存のF01〜F18に対応する場合は、元IDとの対応を先に確認する。
- 全PRD・廃止PRD・作業中の変更を確認し、並行作業では番号を予約・共有する。ファイル数から次番号を推測しない。
- IDを再利用・採番し直さない。分割・統合は新旧の関連をPRDに記録する。

## 同期する際のルール

1. PRDを更新・レビューした後、その版の機能一覧を更新する。
2. 行番号ではなく機能IDで追加・更新する。廃止機能も状態を残す。
3. Sheets側の提案は別タブに置き、採用内容をPRDへ反映する。同じ項目を両方で手修正しない。
4. 元コミット・最終同期日時・結果を記録する。失敗時に最新扱いにせず、同じ版から再実行する。
5. 引き渡し時は対象タグのPRDから作った一覧を固定する。

同期ツールと接続先シートは未設定です。現段階ではこの列定義を使って手動で揃えられます。将来の生成スクリプトは`scripts/`に置き、認証情報はGitへ保存しません。
