# 機能一覧

機能ID・機能名・優先度・仕様状態などの編集元は[機能別PRD](../prd/README.md)です。Google Sheetsは一覧表示・レビュー用に使います。Drive上の整理はユーザーが行い、自動作成・編集はしていません。

## 既存の機能一覧

[アプリの機能要件定義ドラフト](../prd/app-requirements/requirements-draft.md)に18機能（F01〜F18）の一覧があります。[個別PRD](../prd/features/README.md)へ分割済みで、旧IDと新IDは同じF01〜F18です。ドラフトの優先度を承認済みとして扱いません。

## 採番

- 新規の個別PRDは`PCH-F-0001`形式。未使用番号を統合担当が割り当て、PRD作成と同じ変更に含める。既存のF01〜F18に対応する場合は、元IDとの対応を先に確認する。
- 全PRD・廃止PRD・作業中の変更を確認し、並行作業では番号を予約・共有する。ファイル数から次番号を推測しない。
- IDを再利用・採番し直さない。分割・統合は新旧の関連をPRDに記録する。

## 同期する際のルール

1. PRDを更新・レビューした後、その版の機能一覧を更新する。
2. 行番号ではなく機能IDで追加・更新する。廃止機能も状態を残す。
3. Sheets側の提案は別タブに置き、採用内容をPRDへ反映する。同じ項目を両方で手修正しない。
4. 元コミット・最終同期日時・結果を記録する。失敗時に最新扱いにせず、同じ版から再実行する。
5. 引き渡し時は対象タグのPRDから作った一覧を固定する。

接続先は下記の機能要件表です。自動同期ツールは未実装のため、個別PRDの同じIDから手動で揃えます。将来の生成スクリプトは`scripts/`に置き、認証情報はGitへ保存しません。

## 一覧の文章ルール

- 「目的・評価指標」セルは「目的：〜するため」の後に空行を置き、「評価指標：〇〇/〇〇/〇〇」の1行表記にする。指標の間に改行を入れない。
- 「達成条件」は、できればOKと判断できる短い文を1項目1行で記載する。デイリーミッションの4文程度を粒度の目安とする。詳細な検証条件は個別PRDの「詳細な確認事項」に保持する。
- 対象は既存18機能と将来案5件。表現整理でPhase・採用状態や仕様を確定しない。更新履歴は専用タブへ追記する。

## 仕様状態のステータス

| ステータス | 変更する条件 |
| --- | --- |
| モック作成中 | モックを検討・作成しており、チーム内合意を伴う完成が未確認 |
| モック作成完了 | チーム内で合意したモックが完成している |
| モック確定 | POの啓太さんの合意が取れている |
| 廃止 | 対象機能を廃止することが決まっている |

コードや画面が存在するだけで完了・確定にしない。合意者・日付・対象版を個別PRDの履歴へ記録して状態を更新する。2026-09-25の移行時は合意の証跡が未確認のため、23件の旧「草案」を「モック作成中」に変更した。将来案のPhase空欄と採用未決は維持する。仕様状態は合意の進行を表し、本番実装完了を意味しない。「モックの現状」は実際に反映できている範囲を別に記載する。
