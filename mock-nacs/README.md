# mock-nacs：NACS（案件配信サービス）モック

社内の案件配信サービス NACS を、**タメルコから見える振る舞い**の範囲で再現したモック。アプリ（`mock-app/`）・タメルコ管理画面（`mock-admin/`）と同じ `localStorage` の状態（`state.nacs`）を読み書きするので、NACS 側の操作がアプリと管理画面に即時反映される。

- 起動：リポジトリのルートで `npm start` → http://localhost:4173/mock-nacs/
- 先方仕様の転記ではない。poikatsu-spec の `integrations/nacs.md`（依存内容・制約）、`domains/affiliate.md` 3.3〜3.7、`jobs/affiliate-conversion.md` に書かれた「タメルコ側から観測できる振る舞い」を満たすように作っている

## 責務分担（このモックで表現していること）

| NACS が持つ（このモック） | タメルコが持つ（mock-admin / mock-app） |
|---|---|
| 案件の実データ：ID・名称・カテゴリ・広告主／ASP・成果条件・対応 OS・有効期間・配信状態・クリエイティブ | どの画面にどの案件グループを出すか（案件画面設定 `screens`。グループは NACS の**案件一覧コード**を 1 つ持つ） |
| 報酬：広告主報酬（円）× チャネル還元率 → **チャネル向け報酬（計算済み）**。定額／定率／SUR（段階） | 報酬を表示単位（円・pt）へ換算するだけ。率の再計算はしない |
| 案件一覧コードと**掲出順** | 並べ替えない（NACS の順で表示） |
| クリック計測（署名付きクリック URL。前後 30 秒有効） | チャレンジ時に URL を取得して即座に開く。チャレンジの記録は持たない |
| 成果（CV）の発生・**承認**・否認。SUR は段階ごと | マイ案件に NACS の状態をそのまま表示 |
| チャネルへの成果通知（承認・否認） | **承認通知だけ**を消費して付与予定を登録（1 成果 1 回。SUR は段階ごと 1 回）→ 有人審査で確定。チャレンジボーナスの精算も通知受領時 |

## 画面

| 画面 | できること | アプリ・管理画面への効果 |
|---|---|---|
| 案件管理 | 案件の登録・編集・配信停止／再開・削除。報酬種別（定額／定率／SUR）、広告主報酬、チャネル還元率、対応 OS、インストール案件・クレカ、有効期間、クリエイティブ | 配信中・期間内・OS 対応の案件だけが一覧に出る。配信停止した案件の詳細は「見つからない」。期間外は詳細は出るがチャレンジ不可、OS 非対応は「お使いの端末ではチャレンジできません」 |
| 案件一覧コード・掲出順 | コードの作成・削除、候補案件の追加・除外、ピン留め選択。固定以外は3日間のクリック数順で、いま注目の案件（LIST_ALL）は最大100件、ほかの一覧は最大20件。↑↓は固定内の順序を変更。タメルコ側の参照箇所を表示 | 探すのカテゴリ（`tametoku_quick`）やホームの案件グループ（`home`）の中身と並び順が変わる |
| 広告主・ASP | 広告主の登録・編集・削除（案件がある広告主は削除不可） | なし（タメルコからは見えない） |
| クリック計測 | アプリの「チャレンジする」で発行された署名付き URL の一覧 | — |
| 成果（CV）管理 | 成果を発生させる（アプリのクリックなしに再現。定率は注文金額を指定）、承認（SUR は次の段階）、否認 | マイ案件のステータス。承認 → チャネル通知 → 付与予定 |
| チャネル通知 | 通知の停止／再開（障害の再現）、未送信の配信、同じ通知の再送（重複の再現）、タメルコ側の処理結果（付与予定を登録／重複／対象外） | 通知停止中は「マイ案件は承認なのに付与予定がない」状態。再開で追いつく。再送しても付与予定は増えない |
| 操作ログ | NACS 側の操作記録 | — |

## デモの流れ（連動デモ `mock-demo/` にシナリオあり）

1. 案件管理で「ひだまり英会話」を登録し、`LIST_APP` の候補へ追加し、ピン留めする → アプリ「探す」のアプリカテゴリの先頭に出る（タメルコ側の操作なし）
2. 「星ねこクエスト」の広告主報酬を 900 円 → 1,800 円 → アプリのカードが 450 円相当 → 900 円相当
3. 「旅日和トラベル」を配信停止 → アプリの案件詳細が「お探しの案件が見つかりませんでした」
4. 成果を発生 → 承認 → アプリのマイページの準備中が増える（付与予定・有人審査待ち）
5. 同じ承認通知を再送 → 増えない
6. 通知を停止して承認 → マイ案件は承認だが付与予定なし → 再開で追いつく

## 検証

```bash
npm test
```

`mock-nacs/tests/nacs.test.mjs`：報酬計算、登録の妥当性検査、OS・配信停止・期間外の絞り込み、案件一覧コードの掲出順、クリック記録、承認 → 通知 → 付与予定の 1 回制約（再送・SUR 段階）、通知停止と再開、定率案件の換算。

## チャレンジボーナス

`#challenges` で対象案件・開催期間・目標人数・参加人数（デモ）・達成ボーナス（pt）・公開状態を編集し、新規登録できます。「案件詳細を編集」から対象案件の名前・説明・成果条件・通常報酬を編集できます。アプリの表示順はタメルコ管理画面の「チャレンジボーナス」で管理します。


## ピン留め＋3日間のクリック数順（2026-09-16）

「案件一覧コード・掲出順」で、一覧ごとに「先頭に固定する案件」を選んでピン留めできます。

- 固定案件を先頭に並べ、残りはNACSのクリック数が多い順で補充。**固定を含め、いま注目の案件（LIST_ALL）は最大100件、ほかの一覧は最大20件**。ピン留めは各一覧最大20件。
- ピン留めなし、または「すべて解除して自動表示に戻す」を押した場合は、全件を自動選択。
- 集計は**確認日当日を含む3暦日（JST）**。9/16なら9/14 00:00〜9/16分。未来日・9/13以前は除外。直近72時間ではない。
- 件数が同じ（全件0を含む）なら一覧の元の候補順を維持。固定内だけ↑↓で順序変更できる。
- 配信停止・期間外・OS非対応を除いて各一覧の上限まで補充。固定でも配信条件は無視しない。
- 管理画面には集計期間、各案件のクリック数、掲載順、固定状態、各一覧の上限を超えた枠外の案件を表示。枠外の案件を選んで固定可能。
- アプリの利用者条件（金融の除外、インストール案件の未解禁、クレカ画面のカード限定）も上限適用前に絞る。TOPとお得は同じNACSの並び順を使用。
- クリック数は案件単位。NACSの署名付きURL発行時の `recordClick` を集計し、カードの単なる表示や詳細閲覧は数えない。実NACSのAPIには未接続。
- 最新50件のログとは別に `state.nacs.clickDaily` へ日別件数を保存する。旧データは残存ログから移行し、すでに失われた過去ログは復元できない。
- 日付変更・クリック追加・状態変更後の表示時に再計算する。モックの確認日は自動で実日付に進まない。

検証は `tests/click-ranking.test.mjs`。期間境界、同数、固定・解除、注目100件／カテゴリ20件の上限、対象外除外後の補充、旧ログ移行、50件を超える集計の維持を確認する。

「ガポガポ」「すぐできる」も `LIST_ALL` のピン留め・3日間クリック順を使用します。各画面の対象案件に絞ってから最大20件に制限します。キャンペーンページは独立した選択案件の固定順です。クリック順を確かめる場合は、同じオリジン（例：127.0.0.1:4174）のアプリとNACS画面で「チャレンジする」を確定してください。localhost、別ポート、別ブラウザーの記録は共有されません。

## 入稿・掲載準備（2026-10-02）

カタログ入稿 → 掲載審査 → バンドル・掲載設定 → 掲出順を追加。操作・未反映範囲は[F03の運用節](../docs/prd/features/F03-offer-list.md)を参照。サイドバーのチャレンジボーナスは拡張（tier2）として分離した。CSVテンプレートはカタログ入稿からダウンロードできる。実API・認証は接続せず、同一オリジンのlocalStorageで連動する。
