# レシート機能モック

添付の「レシート機能_画面遷移」を参考に、一覧・応募履歴はアプリ、詳細・画像選択・送信・完了はレシキャンWebViewという境界を画面で再現した。実WebView・API・画像アップロード・審査・CSV・ポイント付与には接続しない。

- アプリ：`/mock-app/#home/receipt`、`#receipt-history`
- 自社管理：`/mock-admin/#receipts`。タメルコのみを対象とする。
- 掲載ON/OFF・上下移動は即時保存。同じブラウザ・同じオリジンで反映する。
- 掲載単位はキャンペーン。商品情報・報酬・条件は参照専用。
- 未掲載・終了は新規応募を受け付けない。既存履歴は残る。
- 応募履歴内のデモ操作で判定中→承認→付与済み、判定中→否認を確認できる。既存ポイント残高は変更しない。
- サンプル条件は1キャンペーン1応募、100pt＝1円相当。架空の商品名・報酬・期間であり本番仕様の決定ではない。
- ファイルは最大10MBのJPEG/PNG/WebP。メモリ内プレビューのみ。ブラウザ保存には画像を含めない。
- 本番前に一覧・履歴API、戻り先制御、応募上限、非掲載時の継続応募、判定・付与の同期をレシキャン側と確認する。新規連携の未掲載初期値は運用案。

既存データを変更しないよう `tameruko-receipt-demo-v1` に掲載設定・サンプル応募・掲載変更履歴を保存する。管理画面の複数アプリ設定との連動は対象外。

## 自社独自の販促オプション

`/mock-admin/#receipt-options` で本体とは別に設定する。連動デモは `/mock-demo/?receipt=1&options=1`。商品POP（ホーム・お得・マイページ）、レシートおすすめ枠、自社リッチLP、商品CMを再現する。商品CMは案内4秒→無音演出5秒→獲得表示。スキップ・途中終了は特典なし。JSTの1日初回のみ。実動画SDK・実残高への付与は未接続。

設定は `tameruko-receipt-options-v1`、視聴・表示履歴は `tameruko-receipt-option-activity-v1` に保存し、レシキャンの応募記録を上書きしない。本体の非掲載・終了時は販促も停止する。事前アンケートは対象外。複数商品購入判定・還元アップ・応募上限拡張は本体連携が必要なため未実装。画像入稿や配信期間の個別設定は今後の拡張対象。

## 複数プラン・素材入稿

自社オプションはプラン単位で保存し、1プランに1商品と複数のオプションを設定できる。既存の単一設定は初回読み込み時に1プランへ移行し、保存時に新形式で記録する。

LP画像はJPEG/PNG/WebP、1枚10MB・最大10枚。上から順に表示し、順序変更・削除が可能。CMはMP4/WebM・50MBまで。素材はIndexedDB、設定には素材IDのみを保存する。動画の実再生終了で獲得を再現し、途中終了・再生失敗では付与しない。ブラウザの自動再生制限時は再生ボタンを表示する。未入稿はサンプル表示。素材を読み込んだ後、プランの保存が必要。

おすすめは複数掲載。POP・CMはそれぞれ候補を巡回して1本選択し、全プラン合計で各1日1回の上限を維持する。複数商品の同時購入判定ではなく、複数商品の販促プラン並行運用である。画像・動画の別端末への共有、サーバー配信・本番報酬は未実装。

## POPの共通バナー管理への統合

商品POPの独立配信は廃止した。旧プランにpopup設定が残っていても実行しない。既存の「バナー＆テキスト広告」に画像と `receipt/<キャンペーンID>` または `receipt-lp/<プランID>` のリンクを登録する。AF案件と同じPOP候補・表示頻度・画像寸法ルールを利用する。旧POPは自動的な新規バナー作成を行わない（実バナー画像の入稿が必要）。レシートの商品非掲載・終了、独自LPの停止時は該当するバナーも配信候補から除外する。
